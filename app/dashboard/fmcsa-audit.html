Purpose — FMCSA Audit

This page builds audit-ready DQF packets for an FMCSA compliance review. When an auditor hands you a list of drivers and asks to see specific documents, you select those drivers and the documents requested, and DRIV-EN produces a clean, per-driver PDF packet you can hand over or print.

Why per-driver, and why selective

  • Per-driver — auditors review one driver's file at a time, so each packet is a single driver's documents with a cover page.
  • Selective — you only include what the auditor asked for. You don't volunteer documents that weren't requested.
  • Drug & Alcohol is separate — under 49 CFR 382.401 those records are kept separately and are usually requested on their own.

What each packet contains

  • A cover page: carrier name/DOT/MC, driver name, date generated, and an index of the selected documents with an on-file status for each.
  • The actual documents (images and PDFs) in the order selected, each preceded by an exhibit label.
  • A DRIV-EN footer.

If a selected document isn't on file, the cover page flags it as NOT ON FILE so you can fix the gap before handing the packet over.

Instructions — FMCSA Audit

Step 1 — Select drivers

  1. Use the search box to find a driver by name.
  2. Check each driver the auditor asked to review. You can select multiple.

Step 2 — Select documents

  1. DQF items are checked by default (Application, Employment Verification, MVR, Medical Certificate, Road Test, Annual MVR Review, CDLIS, Safety Performance, TWIC, Hazmat, DL photos).
  2. Drug & Alcohol is a separate category — check it only if the auditor requested those records (they're kept separately per 382.401).
  3. Accidents / Citations is off by default — include only if the auditor asks.

Step 3 — Generate

  1. Review the pre-flight summary — it shows, per selected driver, which selected documents are NOT ON FILE.
  2. Click Generate Packets. DRIV-EN builds one PDF per driver.
  3. If you selected one driver, the PDF downloads directly. If you selected several, they download as a single ZIP.
Tip: Fix any "NOT ON FILE" gaps first by opening the driver's DQF and uploading the missing document, then regenerate. A packet with gaps is still useful, but a complete one is stronger.
